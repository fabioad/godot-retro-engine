# Mega Drive → SNES porting in the engine

The `Mega Drive project → SNES` Game Build mode now has a **source-level port
registry** (`md_to_snes_port.gd`) instead of always exporting a static stage.
The registry chooses the faithful path that exists for the source format.

## What "faithful" can mean

A Mega Drive game is 68000 machine code. Interpreting 68000 on a 3.58 MHz
65816 in real time is not viable, so a faithful SNES port must translate the
game logic, not the instruction stream. The engine supports that at three
levels:

| Source format | Path | Fidelity |
| --- | --- | --- |
| Engine-native project (Godot/native port bundle or generated MD project) | shared actor/state runtime generator | Faithful to the engine's portable semantics: stage, actors, animations, solids, UI widgets, input and camera |
| Sonic 2 disassembly | dedicated source adapter (`sonic2_snes_port.py`) | EHZ engine data + physics slice; remaining Sonic systems are per-game work |
| Arbitrary Mega Drive ROM/disassembly | none automatically | Needs a per-game source adapter. A binary translator/emulator is not provided. |

The registry returns a clear error for a raw 68000 project without a portable
engine representation, rather than silently exporting a stage viewer and
calling it a port.

## Native projects (the general path)

A project generated by the engine keeps its native port bundle in the project
metadata (`native_port`). The port path now:

1. finds the port bundle in `native_links.json` **or** in
   `metadata.native_port`;
2. loads the stage from the bundle's `stage.stage_json`;
3. loads actors/animations from the bundle JSON, resolving assets against the
   bundle source root when the generated project does not contain them;
4. reuses `_write_snes_runtime()` to generate the same actor states, solids,
   UI widgets, camera and input handling on the SNES.

Verified with the `large_ssf2` native project:

```text
source:    Mega Drive native project (32x28 stage, 1 actor, 1 widget, 1 solid)
export:    megadrive_snes
ROM:       262,144 bytes, LoROM, checksum OK
runtime:   actors=1 widgets=1 solids=1
preview:   SCORE/START widget and runtime frame visible
```

Because both targets use the same runtime generator, a game authored in this
portable format is translated by the engine itself; no per-game 68000
reimplementation is needed.

## Sonic 2 adapter

`megadrive_snes` on a Sonic 2 disassembly uses
`ide/addons/retro_engine/tools/sonic2_snes_port.py`. It reads the original
Kosinski level/collision/sprite data and writes a PVSnesLib project with:

- full EHZ Act 1, original tiles/map/palette, streamed in 43x4 BG pages;
- original 16x16 collision indexes and heightmaps;
- Sonic sprite frames (idle/walk/run/roll) as SNES OBJs;
- camera, ground acceleration, jump, gravity, air control and air floor/ceiling
  collision;
- 226 rings from the original ring list, with collection and score;
- SCORE/TIME/RINGS HUD;
- springs, monitors, star posts, the goal signpost, spikes and the EHZ
  badniks (Buzz Bomber, Masher, Coconuts) on a BG2 object layer, using the
  original Nemesis art and sprite mappings;
- hurt/death poses, ring scatter, lives, checkpoint respawn and pit deaths.

See `SONIC2_SNES_PORT.md` for the verified screenshots and the remaining Sonic
systems (slopes/loops, badnik projectiles, game-over/lives HUD, audio,
Tails/specials/openings/ending). Those are per-game adapter work, not a missing
generic translation step.

## Why not "any ROM" automatically

A faithful binary translator would have to recompile 68000 instructions,
self-modifying code, VDP/Z80/YM2612 hardware access and timing into 65816 code
and SNES peripherals. That is a research project, not a build setting, and the
SNES CPU cannot emulate the 68000 at the original speed. The engine therefore
translates **portable game representations** and ships adapters for known
source trees. For another original game, the work is a source-level engine port
like the Sonic 2 adapter.

## Usage

1. Import/open a Mega Drive project.
2. Game Build → `Mega Drive project → SNES`.
3. Generate + Build.
4. For a native project the runtime/stage is translated; for Sonic 2 the
   adapter runs; for an unsupported raw project the log explains that a
   per-game adapter is required.
